## transformers 4.x API changes / traps (P3 depends on this)

1. **Pipeline call unchanged:** `pipeline("feature-extraction", "Xenova/all-MiniLM-L6-v2", { dtype: "q8", device: "wasm" })` is valid in 4.3.1. `q8` maps to suffix `_quantized` → `onnx/model_quantized.onnx` (`DEFAULT_DTYPE_SUFFIX_MAPPING`); `device:"wasm"` defaults dtype to q8 (`DEFAULT_DEVICE_DTYPE_MAPPING`). `{ pooling: "mean", normalize: true }` and `out.dims` unchanged.
2. **Browser bundle keeps two bare imports:** `import * as ONNX_WEB from "onnxruntime-web/webgpu"` and `import { Tensor } from "onnxruntime-common"` (esbuild externals — `onnxruntime-web` is a real dependency, not inlined). Serving `transformers.web.js` raw to a browser requires an **import map**, and *both* specifiers must map to the **same** ORT module URL so there is a single ORT instance (`Tensor` is re-exported by the ORT bundle; mapping `onnxruntime-common` to a separate copy risks `instanceof` mismatches). Under Next/webpack these resolve at build time — P3 must confirm the bundler resolves `onnxruntime-web/webgpu` and that only one copy lands in the chunk.
3. **Offline wasm paths must be overridden:** 4.x sets `wasmPaths` to a `https://cdn.jsdelivr.net/npm/onnxruntime-web@…` object at *import time* if unset — that would break `connect-src 'self'` and offline, so set `env.backends.onnx.wasm.wasmPaths` explicitly (after import).
4. **`env.useWasmCache` trap (measured):** default is `true` when `caches` exists. It only engages when `wasmPaths` is an **object** with `mjs`+`wasm` keys: it preloads the factory and swaps it for a `blob:` URL, then dynamic-imports it — **blocked** by the app CSP (`script-src 'self' 'unsafe-inline' 'wasm-unsafe-eval'`, no `blob:`):
   `[page] Loading the script 'blob:http://127.0.0.1:4399/…' violates … "script-src 'self' 'unsafe-inline' 'wasm-unsafe-eval'"` → `[pageerror] no available backend found. ERR: [wasm] TypeError: Failed to fetch dynamically imported module: blob:…`
   Two working fixes, both verified: (a) string form `wasmPaths = "/ort/"` (skips the cache path entirely — this is what the plan specified, kept as default), or (b) object form + `env.useWasmCache = false` (test C, passes).
5. **ORT resolution:** `onnxruntime-web` is not hoisted; found at `node_modules/.pnpm/onnxruntime-web@1.31.0-dev.20260914-8d85527a0/node_modules/onnxruntime-web/dist`. The webgpu entry dynamically imports the factory `ort-wasm-simd-threaded.asyncify.mjs` and locates the `.wasm` via `locateFile = prefix + fileName` (no Range requests — a plain static server suffices).
6. **Tokenizers are pure JS in 4.x** (`@huggingface/tokenizers@0.2.0` bundled; no wasm artifact) — only `tokenizer.json` + `tokenizer_config.json` fetched.
7. `env.allowRemoteModels=false`, `env.allowLocalModels=true`, `env.localModelPath="/models/"` and `env.backends.onnx.wasm.numThreads=1` (no COOP/COEP → no SharedArrayBuffer) all behave as the plan expects.

## Deviations from the plan (all minimal, in spike-only code)

- `run.mjs` index.html adds an **import map** for the two bare ORT specifiers (point 2 above) — required for transformers 4.x.
- `ortDir` resolved by scanning `node_modules/.pnpm/onnxruntime-web@*` instead of a literal path (pnpm non-hoisting).
- `run.mjs` logs every request + status (`SERVED`) and sets `content-length`; `/ort/` falls back to the transformers dist copy of the factory if ORT dist lacks the requested file.
- `page.js` adds a `securitypolicyviolation` counter (`cspViolations`) and env-var/query switches used only for tests A/B/C; the primary configuration (string `wasmPaths`, webgpu bundle) is exactly the plan's.
- `pnpm add -w @huggingface/transformers` was done by the orchestrator before this spike; not re-run here (S1 builds concurrently).
