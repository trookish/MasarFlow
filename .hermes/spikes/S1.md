# Spike S1 — Next standalone + pnpm + electron-builder on Windows

**Date:** 2026-10-17 · **Branch:** release/v0.2.0 (in place, no spike branch) · **Env:** Windows 11, git-bash, node v24.14.0 (system), pnpm 11.21.0, Next 16.3.0 (Turbopack), electron-builder 26.15.3, electron 43.4.0.

## Verdict

**GO — via NO-GO fallback (a) `node-linker=hoisted`, plus one required electron-builder config fix.**

Two blockers were found with the plan's exact recipe; both have working fixes, verified end-to-end:

1. **Default pnpm (symlinked) layout produces a standalone server that cannot boot on Windows.** Next's standalone copy recreates pnpm's directory symlinks as *file-type* symlinks pointing at directories; every `fs.realpathSync` through them fails with `EPERM` and the server crashes at require time. Fallback (a) — hoisted layout — eliminates all symlinks (25 → 0) and the server boots and serves.
2. **electron-builder silently drops a root-level `node_modules` from `extraResources`.** With the plan's entry (`{from: app-server, to: app-server}`) the packaged tree had `.next`, `public`, `src`, `server.js` but **0 of 1108** `node_modules` files. It "ran" from `win-unpacked` only by resolving modules upward into the repo (trap: in-place boot proves nothing). Root cause is hard-coded in `app-builder-lib/out/util/filter.js`: `if (relative === "node_modules") return false;` — `filter` patterns cannot override it. Fix: copy `app-server/node_modules` via its **own** extraResources entry (paths inside it are `next/...`, `react/...`, never the exact string `node_modules`).

With both fixes: `desktop/dist/win-unpacked/resources/app-server` contains the complete server (5883 files, 69,671,999 bytes — exact parity with source), 0 symlinks, and boots from an **isolated temp dir outside the repo** with `/dashboard` → 200 and a real chunk → 200 (byte-identical to on-disk files). No `node_modules` install needed on the target.

## Key findings / surprises

1. **File-type dir symlinks → EPERM (the first crash).** Boot of `.next/standalone/server.js` died with:
   `EPERM: operation not permitted, stat '...\.next\standalone\node_modules\.pnpm\next@16.3.0_...\node_modules\react'` (via `realpathSync` in next's require-hook).
   Repro + diagnosis: the standalone links carry attributes `Archive, ReparsePoint` (no `Directory` flag) = file-type symlink to a directory; a `fs.symlinkSync(t,'l','file')`→`statSync` EPERM / `'dir'`→OK test in scratch confirms the discriminator. The repo's own pnpm links are dir-type (`Directory, ReparsePoint`) and work. So Next's standalone copy mis-types these links on Windows — it is NOT a machine/permissions problem, and NOT specific to this repo (any pnpm-isolated Next build on Windows hits it). Hoisted layout is the clean escape (0 symlinks).
2. **electron-builder root-`node_modules` drop.** `extraResources: [{from: app-server, to: app-server}]` produced 4775/5883 files — every file under the top-level `node_modules` was missing. In-place `/dashboard` from `win-unpacked` returned 200 anyway (module resolution walked up into the repo root's hoisted `node_modules`). Isolated copy proved it: `Error: Cannot find module 'next'` (`RequireStack: ...\s1-isoB\server.js`). Root cause: `app-builder-lib/out/util/filter.js` `createFilter()` line ~43 hard-returns `false` for `relative === "node_modules"` (built for the app-`files` flow; applies to `extraResources`/`extraFiles` too; `filter: ["**/*"]` cannot override). Working minimal fix (verified, 1108/1108 files copied):
   ```yaml
   extraResources:
     - {from: app-server, to: app-server}
     - {from: app-server/node_modules, to: app-server/node_modules}
   ```
   (afterPack-hook copy and zip-plus-extract also work around it if a declarative fix is ever impossible; NSIS installer path not tested.)
3. **`pnpm 11` ignores `node-linker` in `.npmrc`** (moved to `pnpm-workspace.yaml`; `pnpm config get node-linker` → `undefined` with the plan's `.npmrc` in place). Applied via CLI instead: `pnpm install --config.node-linker=hoisted`. The relink itself took ~30 s, but the install process then hung in an endless "GET ... error (23), retrying" loop fetching **foreign-platform optional** binaries (`@next/swc-darwin-*`, `-linux-*`, `@esbuild/netbsd-*`). Linking was already complete at that point; I killed my own process (PID 2716) after ~15 min. `next`, `react`, `@next/swc-win32-x64-msvc` etc. all present; every build/boot after that was clean.
4. **Pre-existing `next build` TS-gate failure (not caused by this spike).** `tests/unit/desktop/{ports,token,url-policy}.test.ts` (committed) import `@desktop/backend/*` and `@desktop/security/url-policy`, which exist under `desktop/src/main/`, but the root `tsconfig.json` has only `@/*` paths → `TS2307` in `next build` and in `pnpm typecheck`. The spike's throwaway config used `typescript: {ignoreBuildErrors: true}` to get past it (reverted). **P1.T3 must fix properly** (add `@desktop`/`@desktop-shared` path mappings, or exclude `tests/**` from the build's type check).
5. Next's standalone output does **not** include `public/` or `.next/static/` (documented); they must be copied into the tree before shipping. Done here before the copy to `desktop/app-server`, so the packaged artifact includes them.
6. `outputFileTracingExcludes` key semantics (per `node_modules/next/dist/docs/.../output.md`): keys are **route globs**; the documented global key is `'/*'`, not `'*'` (picomatch `*` does not cross `/`, so `'*'` matches no route). Used `'/*'`.
7. Observation, not attribution: S3's `:4399` listener was gone after the workspace-wide hoisted relink. I never killed any sibling process. A future plain `pnpm install` will relink `node_modules` back to the default isolated layout — coordinate before running one.

## Fallbacks attempted (plan order)

- (a) `node-linker=hoisted` + rebuild — **applied and effective** (with the CLI adaptation from finding 3). All boot/serving criteria measured only after this.
- (b) `pnpm deploy --prod` — **not needed**, and it would not have fixed finding 2 (that drop is electron-builder-side, layout-independent).
- (c) stop and report — not needed.

## Deviations from the plan (and why)

1. `outputFileTracingExcludes` key `"*"` → `"/*"` (documented global route-glob; see finding 6). Directory list unchanged.
2. `typescript.ignoreBuildErrors: true` added to the throwaway `next.config.ts` solely to get past the pre-existing TS-gate failure (finding 4). Reverted with the rest of the config.
3. Fallback (a) applied via `--config.node-linker=hoisted` CLI flag instead of the plan's `.npmrc` (pnpm 11 ignores it; the real home is `pnpm-workspace.yaml`, which another agent had modified — not touched).
4. electron-builder `extraResources` extended with the second `app-server/node_modules` entry (finding 2). Both config files reverted afterwards for P1.T3 to re-apply properly.
5. Server log in `C:\Users\trookish\AppData\Local\Temp` instead of `/tmp`; servers stopped via `netstat -ano | grep <port>` + `powershell Stop-Process` (PIDs confirmed to be my `node ...server.js` before kill).

## State left behind (full disclosure)

- `next.config.ts` and `desktop/electron-builder.yml` reverted (`git checkout --`); `.npmrc` removed; `desktop/app-server/`, `desktop/dist/`, `.next/standalone/public`, `.next/standalone/.next/static` deleted; all spike servers stopped (ports 3123–3127 free); temp copies removed.
- **`node_modules` on disk is currently a HOISTED layout** (git-invisible; `.modules.yaml` says `nodeLinker: hoisted`, no `.pnpm` at root). All tools work on it. Any later `pnpm install` without the flag will relink it to the default isolated layout and re-create findings 1's conditions. Deliberately left in place (reverting = a second workspace-wide relink that could disrupt concurrently running siblings); flag if you want it reverted first thing.
- `.next/` is the spike's hoisted build output (no `standalone/public` or `standalone/.next/static` inside anymore). `pnpm-lock.yaml` untouched by the installs (resolution step was skipped throughout).
- Temp artifacts under `%LOCALAPPDATA%\Temp\s1-*.{log,list,...}` kept for forensic quoting; safe to delete.

## Recommendation for P1.T3 / packaging

- Keep `output: "standalone"`, `outputFileTracingRoot`, `outputFileTracingExcludes` with the `'/*'` key.
- Decide `node-linker=hoisted` (repo-wide, in `pnpm-workspace.yaml`) — required for a bootable standalone on Windows until Next stops mis-typing links.
- Use the two-entry `extraResources` (or an `afterPack` copy) — verify with a file-count parity check (`source == resources/app-server`, here 5883) and an isolated-dir boot test; **never** validate by booting from inside the repo tree.
- Add a CI/harness check: `find <tree> -type l | wc -l == 0` (symlink guard) — finding 1 is currently invisible until runtime.
