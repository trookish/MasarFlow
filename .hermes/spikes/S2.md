# Spike S2 — `masarflow://` proxy: streaming, redirect, stable origin

**Verdict: GO** (all P0.T5 criteria pass). One mandatory Electron API adjustment found:
the `protocol.handle` proxy must be built on **`net.request`**, not `net.fetch` — `net.fetch`
cannot pass a 3xx through to the navigation (`redirect: "manual"` is broken upstream), and
`redirect: "follow"` silently absorbs the redirect so the page URL never leaves `/`.

- Date: 2026-10-17 · Electron **43.4.0** (`desktop/node_modules/electron`, run via `desktop/node_modules/.bin/electron`) · Node **24.14.0** · Windows 11 · git-bash
- Ran as plain script (`electron main.cjs`), `S2_OUT` set per run; both final runs exit code 0
- `app.getPath("userData")` (printed in every run): `C:\Users\trookish\AppData\Roaming\Electron` (default app name — see "notes")
- `server.cjs` used exactly as written in the plan (no changes), including the `x-masarflow-token` check and 307 on `/`

## What failed first: `net.fetch` with `redirect: "manual"` (plan code as written)

Run 1 of the plan's `main.cjs` verbatim (handler = `net.fetch(..., { redirect: "manual" })`)
failed — real output:

```
userData: C:\Users\trookish\AppData\Roaming\Electron
Error: Redirect was cancelled
    at SimpleURLLoaderWrapper.<anonymous> (node:electron/js2c/browser_init:2:139006)
    at SimpleURLLoaderWrapper.emit (node:events:509:28)
(node:18468) electron: Failed to load URL: masarflow://app/ with error: ERR_UNEXPECTED
(node:18468) UnhandledPromiseRejectionWarning: Error: ERR_UNEXPECTED (-9) loading 'masarflow://app/'
    at rejectAndCleanup (node:electron/js2c/browser_init:2:94962)
    at WebContents.finishListener ... (rejection id: 1)
```

Then the process **hung** (no JSON, no exit; killed by `timeout` → exit 124; the trailing
"Network service crashed / GPU process exited unexpectedly: exit_code=143" lines in that run
are effects of the forced SIGTERM, not of the handler). The unhandled rejection happens
because the plan's `app.whenReady().then(...)` chain has no `.catch` — added in the fix.

Root cause (verified in the v43.4.0 sources, not guessed):
- `net.fetch` builds a `ClientRequest` with `redirect: req.redirect` but registers **no**
  `redirect` listener (`lib/browser/api/net-fetch.ts`).
- `ClientRequest` with redirect policy `manual` calls `this._die(new Error('Redirect was
  cancelled'))` unless a `redirect` listener calls `followRedirect()`
  (`lib/common/api/net-client-request.ts`).
- Upstream: electron/electron#43715 "[Bug]: net.fetch fails on manual redirect" — "This is
  working as documented… We are missing the handling of `redirect` event in the implementation today."

## Exact code that worked (`main.cjs`, final)

Deviations from the plan are marked; everything else is the plan's code verbatim.

```js
const { app, BrowserWindow, protocol, net } = require("electron");
const { spawn } = require("node:child_process");
const { writeFileSync } = require("node:fs");
const { Readable } = require("node:stream");                    // + added
const path = require("node:path");

protocol.registerSchemesAsPrivileged([
  { scheme: "masarflow", privileges: { standard: true, secure: true, supportFetchAPI: true, corsEnabled: true, stream: true } },
]);

app.whenReady().then(async () => {
  console.log("userData:", app.getPath("userData"));           // + added (cleanup identification)
  const port = 41000 + Math.floor(Math.random() * 1000); // different every run on purpose
  const token = "tok-" + Math.random().toString(16).slice(2);
  // Plain `node` from PATH (Electron's own binary cannot run a script without ELECTRON_RUN_AS_NODE).
  const child = spawn("node", [path.join(__dirname, "server.cjs"), String(port)], {
    env: { ...process.env, MASARFLOW_TOKEN: token }, stdio: "ignore",
  });
  child.on("error", () => {});
  await new Promise((r) => setTimeout(r, 800));

  // ± REPLACED the net.fetch proxy: net.fetch cannot pass a 3xx through (`redirect:
  // "manual"` dies with "Redirect was cancelled", electron/electron#43715). net.request
  // exposes the 3xx via its `redirect` event instead.
  protocol.handle("masarflow", (request) => {
    const u = new URL(request.url);
    const target = `http://127.0.0.1:${port}${u.pathname}${u.search}`;
    const headers = new Headers(request.headers);
    headers.set("x-masarflow-token", token);
    return new Promise((resolve, reject) => {
      const req = net.request({ url: target, method: request.method, redirect: "manual", headers: Object.fromEntries(headers) });
      let settled = false;
      req.on("redirect", (statusCode, _method, redirectUrl) => {
        if (settled) return;
        settled = true;
        const loc = new URL(redirectUrl, target);
        resolve(Response.redirect(`masarflow://app${loc.pathname}${loc.search}`, statusCode));
        req.abort();
      });
      req.on("response", (resp) => {
        if (settled) return;
        settled = true;
        const stream = new ReadableStream({
          start(c) {
            resp.on("data", (d) => c.enqueue(new Uint8Array(d)));
            resp.on("end", () => c.close());
            resp.on("error", (e) => c.error(e));
          },
        });
        const h = {};
        for (const [k, v] of Object.entries(resp.headers)) h[k] = Array.isArray(v) ? v.join(", ") : v;
        resolve(new Response(stream, { status: resp.statusCode, statusText: resp.statusMessage, headers: h }));
      });
      req.on("error", (err) => { if (!settled) { settled = true; reject(err); } });
      if (request.body) Readable.fromWeb(request.body).pipe(req); else req.end();
    });
  });

  const win = new BrowserWindow({ show: false, webPreferences: { sandbox: true } });
  await win.loadURL("masarflow://app/");
  const result = await win.webContents.executeJavaScript(`(async () => {
    ... (plan page script, unchanged) ...
  })()`);
  writeFileSync(process.env.S2_OUT, JSON.stringify({ port, userData: app.getPath("userData"), ...result }));
  child.kill(); app.exit(0);
}).catch((e) => {                                               // + added: write failure JSON, exit 1
  writeFileSync(process.env.S2_OUT, JSON.stringify({ error: String((e && e.stack) || e) }));
  app.exit(1);
});
```

## Other Electron 43.4.0 findings

- `protocol.registerSchemesAsPrivileged` privileges object accepted verbatim
  (`standard`, `secure`, `supportFetchAPI`, `corsEnabled`, `stream` all exist in
  `electron.d.ts` `Privileges`). fetch(), IndexedDB, SSE all work under the scheme.
- `bypassCustomProtocolHandlers` is a typed `net.fetch` RequestInit extension and works.
  `duplex: "half"` is untyped but accepted at runtime. Both were exercised on p1
  (`net.fetch` handler): 1 MiB POST + incremental SSE (stamps `[256,507,760,1024,1274]`) — so
  `net.fetch` itself is fine for bodies/streaming; only redirects force `net.request`.
- `Response.redirect("masarflow://app/…", 307)` is accepted and followed by the top-level
  navigation (proven by p1 + p2).
- `net.request` response (`IncomingMessage`) → `new Response(readableStream, …)` streams
  incrementally through the protocol (SSE stamps ~250 ms cadence in all runs).
- The plan's main-process code hangs forever if `loadURL` rejects (unhandled rejection,
  no exit). Any production version must surface/catch this (added here).

## Deviations from the plan (all minimal, all measured)

1. Handler built on `net.request` + `redirect` event instead of `net.fetch` (required for
   criterion 1 — see above). input body forwarding via `Readable.fromWeb(request.body).pipe(req)`.
2. `userData` added to the run JSON + `console.log` (task requires printing it for cleanup).
3. `.catch` on the `whenReady` chain writing an error JSON and `app.exit(1)` (plan's code hangs on failure).

## Gaps / assumptions (for P1.T4)

- Redirect mapping assumes the redirect target is **same-origin with the local server**
  (path+search re-hosted under `masarflow://app`). A redirect to an external URL would be
  mis-mapped; untested.
- No backpressure plumbed on the response-body bridge (fine at spike scale; revisit).
- Redirect of a **POST with a body** is untested (probe aborts before upload completes).
- Cookies/credentials forwarding not exercised (`net.request` default = no session cookies).
- Single hidden window only; no multi-window / service-worker sessions tested.
- Server-down case: handler rejects → navigation `ERR_UNEXPECTED` (no friendly error page).
