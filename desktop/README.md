# MasarFlow desktop shell

The Electron app that *is* MasarFlow. Its window hosts the Next app from `../src`, served by an embedded
Next server that binds `127.0.0.1` and checks a per-launch token. There is no separate launcher and no
browser build. The system shape is in [docs/architecture.md](../docs/architecture.md); the dev loop and
test commands are in [docs/development.md](../docs/development.md).

```
desktop/
  src/
    main/       Electron main process
      backend/  embedded Next server, launch token, masarflow:// protocol, ports
      security/ CSP, permissions, navigation policy, folder allow-list (roots.json)
      git/      git service behind the preload bridge
      ipc/      IPC handlers: terminal (node-pty), logs, app actions
      windows/  the frameless main window
      backups.ts, diagnostics.ts, logging.ts, secrets.ts, settings.ts, updater.ts
    preload/    contextIsolated bridge (window.masarflow)
    shared/     types shared by main, preload and the renderer (@desktop-shared/*)
  resources/    build resources (app icon)
  scripts/      proof-update-local.mjs (local auto-update proof)
  app-server/   assembled Next standalone server (generated by `pnpm build:app`)
```

## Scripts

Run these from the repository root.

| Script | Purpose |
| --- | --- |
| `pnpm dev` | `next dev` plus Electron pointed at it, with HMR |
| `pnpm build:app` | Embedding assets, Next standalone build, `desktop/app-server/` |
| `pnpm desktop:dist:dir` | `build:app` + unpacked app in `desktop/dist/win-unpacked/` |
| `pnpm desktop:dist` | `build:app` + NSIS installer, portable exe and `latest.yml` in `desktop/dist/` |
| `pnpm desktop:typecheck` | `tsc -p desktop/tsconfig.node.json --noEmit` |
| `pnpm smoke:desktop` | Boots the packaged app and waits for `SMOKE_OK` |
| `pnpm e2e:desktop` | Playwright specs against the packaged app |

## Windows SmartScreen ("Windows protected your PC")

The installers are **not code-signed**, so SmartScreen warns the first time they run. To run one:

- Click **More info → Run anyway**, or
- Right-click the file → **Properties → General → Unblock → OK**, then run it.

With **Smart App Control** enabled on Windows 11 there is no "Run anyway": unblock the file first, or turn
Smart App Control off (Windows Security → App & browser control).

electron-builder signs automatically when `CSC_LINK` and `CSC_KEY_PASSWORD` are set, so a code-signing
certificate (OV/EV) removes the warning without further changes.

## Notes

- `node-pty` ships N-API prebuilds that are ABI-stable across Node and Electron, so no native rebuild is
  needed (`npmRebuild: false` in `electron-builder.yml`).
- Windows x64 is the only validated platform. The `mac` and `linux` blocks in `electron-builder.yml` are
  not built or tested.
